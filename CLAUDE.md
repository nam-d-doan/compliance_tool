# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Banking compliance management SPA (regulations, obligations, evidence, CAPs, NCCs, licenses, reports/EWS, admin), built with React 19, TypeScript 6, Vite 8, Tailwind 4 and shadcn/ui. It is a **frontend-only prototype**: every `/api/*` call is served by an in-browser mock layer. There is no backend.

This repo keeps per-directory work contracts in `DOX.md` files (`./DOX.md`, `src/DOX.md`, `src/mocks/DOX.md`, `docs/DOX.md`). Read the relevant one before changing a subtree, and update it when you change the contract it describes.

## Commands

Use **pnpm only** (not npm or yarn).

```bash
pnpm install
pnpm dev                 # Vite dev server with the direct-fetch mock API
pnpm build               # tsc -b && vite build (this is the type check)
pnpm lint                # oxlint (skips src/components/ui/)
pnpm preview
VITE_ENABLE_MSW=1 pnpm build && pnpm preview   # prod build with the MSW service worker
prek run --all-files     # pre-commit hooks; must pass before committing
```

There is no test runner. Before you call a change done, check it with `prek run --all-files`, `pnpm build` and `pnpm lint`.

Demo login: `admin@demo.com` / `demo1234`. `src/constants/demo-users.ts` has one account per role (admin, executive, owner, approver, reviewer), all with the same password.

## Architecture

**Data flow:** `mocks/handlers/` → `services/*_service.ts` (singleton objects over `lib/api.ts` fetch wrappers) → TanStack Query hooks (`hooks/queries/`, `hooks/mutations/`, with keys from the factory in `hooks/query-keys.ts`) → `components/[domain]/` and `pages/[domain]/`. Types are per domain in `types/`, re-exported from `types/index.ts`. Endpoint paths live in `constants/api.ts`.

**The mock layer has two modes** (`src/main.tsx`):
- **Dev:** `mocks/directApi.ts` overrides `window.fetch` and dispatches through **its own `routes` table**. It also unregisters any service worker and clears caches on startup. Do not start MSW in dev.
- **Prod:** the MSW worker (`mocks/browser.ts`, using the arrays in `mocks/handlers/index.ts`) runs only when `VITE_ENABLE_MSW=1`. Otherwise requests go to `VITE_API_URL`.
- Both modes call the same handler functions exported from `handlers/[domain]_handlers.ts`. **A new endpoint must be registered in both places:** the file's MSW `http.*` array and the `routes` array in `directApi.ts`. If you miss one, it works in one mode and 404s in the other. (`src/mocks/DOX.md` only lists the MSW step.)
- `mocks/db.ts` is an in-memory singleton (`getDb()`) seeded with `faker.seed(42)`. It resets on every page reload.

**Auth and RBAC:** A Zustand `authStore` persists to the `localStorage` key `auth-storage`, and `lib/api.ts` reads the token from there. Role order is admin > executive > owner > approver > reviewer (`constants/rbac.ts`). Per-route access is in `ROUTE_PERMISSIONS` (`constants/routes.ts`), and `buildNavTree(role)` builds the sidebar.

**Routing:** `routes/index.tsx` defines one `createBrowserRouter`. Every page is loaded with `React.lazy`. Protected routes sit under `ProtectedRoute` + `MainLayout`.

**Adding a feature, in order:** types → `mocks/db.ts` data → handler (both registrations) → service → query/mutation hooks → components (with a barrel `index.ts` per domain) → page → route plus `ROUTE_PERMISSIONS`.

## Conventions

- Path alias: `@/` → `src/`.
- `src/components/ui/` is generated by shadcn. Don't hand-edit it; add components with `pnpm dlx shadcn@latest add <name>`. Don't hand-edit `public/mockServiceWorker.js` either; regenerate it with `pnpm dlx msw init public/ --save`.
- UI work must follow `docs/architecture/design-language.md` (hero banners, callouts, KPI cards, fact grids, AI reason lists, frosted-glass overlays).
- For current behavior, trust `docs/USER_FLOW.md`. The `docs/specs/` P1–P5 files are historical and aspirational, and prettier deliberately skips them.
- Commits use the Conventional format. Allowed types: `feat`, `fix`, `improve`, `style`, `env`, `docs`, `refactor`, `ci`, `test`, `chore`, `git`, `wip`. Hooks also run the betterleaks secret scan, prettier and oxlint.
- The app deploys to Vercel (see `docs/deployment.md`). `vite.config.ts` sets `server.allowedHosts: true` so cloudflared tunnels work.
