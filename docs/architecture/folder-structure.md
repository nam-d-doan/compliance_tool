## Key Architectural Decisions

### 1. Module Organization

- **Domain-driven**: Each feature (compliance, evidence, etc.) has its own components, services, and hooks
- **Cross-cutting**: Common components, UI components, and AI features are separated
- **Lazy loading**: Routes will use React.lazy() for code splitting

### 2. Data Layer Architecture

```
MSW v2 Handlers → Services → React Query → UI Components
                      ↓
                  Query Keys (factories)
                      ↓
                  Mock DB (singleton)
```

### 3. State Management

- **Auth**: Zustand store (user, role, token)
- **Server State**: TanStack Query with query keys factory pattern
- **UI State**: Local component state or Zustand for global UI (theme, notifications)

### 4. Query Key Strategy (Example)

```typescript
// hooks/query-keys.ts
export const complianceKeys = {
  all: ["compliance"] as const,
  lists: () => [...complianceKeys.all, "list"] as const,
  list: (filters: ComplianceFilters) =>
    [...complianceKeys.lists(), filters] as const,
  details: () => [...complianceKeys.all, "detail"] as const,
  detail: (id: string) => [...complianceKeys.details(), id] as const,
};
```

### 5. MSW v2 Handler Pattern

```typescript
// mocks/handlers/compliance_handlers.ts
export const complianceHandlers = [
  http.get("/api/compliance", ({ request }) => {
    const url = new URL(request.url);
    const filters = parseFilters(url.searchParams);
    const items = getComplianceItems(filters);
    return HttpResponse.json({ items, total: items.length });
  }),
  http.post("/api/compliance", async ({ request }) => {
    const body = (await request.json()) as CreateComplianceDTO;
    const created = createComplianceItem(body);
    return HttpResponse.json(created, { status: 201 });
  }),
];
```

### 6. Route Protection Strategy

```typescript
// components/navigation/ProtectedRoute.tsx
export const ProtectedRoute = ({ children, requiredRole }: Props) => {
  const { user, isAuthenticated, role } = useAuthStore()
  const hasPermission = requiredRole ? checkRole(role, requiredRole) : true

  if (!isAuthenticated) return <Navigate to="/login" replace />
  return hasPermission ? <>{children}</> : <Navigate to="/unauthorized" />
}
```

## Development Workflow

### 1. Component Development Pattern

1. Define types in `types/[domain].ts`
2. Create mock data in `mocks/db.ts`
3. Write MSW handlers in `mocks/handlers/[domain]_handlers.ts`
4. Build service functions in `services/[domain]_service.ts`
5. Create query hooks in `hooks/queries/` and `hooks/mutations/`
6. Build UI components in `components/[domain]/`
7. Assemble pages in `pages/[domain]/`

### 2. Testing Strategy (Optional)

- UI Tests: Testing Library with MSW
- Component Tests: Storybook
- E2E: Playwright (if needed)

### 3. Performance Optimizations

- React.lazy() for route components
- useMemo/useCallback for expensive operations
- QueryClient defaults: staleTime, gcTime
- Debounced search inputs
- Virtualization for large tables (tanstack/react-table)
