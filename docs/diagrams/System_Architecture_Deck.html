01 · Context

What this system is — and is not

A purpose-built compliance management platform for a Vietnamese commercial bank, grounded in real regulation research (SBV circulars, AML Law, Basel III). Tracks the full obligation lifecycle and surfaces risk early via an EWS report.

DOMAIN

📜 Regulation Library

13 curated regulations (Law CI 2024, Cir14/2025 Basel III, AML Law 14/2022…) with dependencies and article-level obligations.

CORE

⚖️ Obligations

Unified Obligation entity with effective status derived from linked CAPs: completed only when all CAPs closed.

REMEDY

🛠️ CAP & NCC

Corrective Action Plans (Open → Pending Approval → Closed) and Non-Compliance Cases with 3-step investigation flow.

FLOW

📨 Assignments

Obligations dispatched to owner units; acknowledge / cancel / track to closure.

SIGNAL

🚨 EWS Report

Early Warning System — trends NCC data into forward-looking risk signal for executives.

AI

🤖 AI Augmentation

Copilot, CAP generation, compliance risk scoring, regulation impact, exec summary — all human-in-the-loop.

Prototype today. Frontend-only React SPA with an MSW (Mock Service Worker) API — no real backend. This deck depicts the target architecture: app server, real PostgreSQL, AI platform, and bank integration via ESB.

03 · Roadmap state

Current vs Target

The deployed prototype vs the production target this architecture moves toward.

◐ Current — Prototype

  • Frontend-only React 19 SPA, Vite, deployed on Vercel
  • MSW mock API — handlers in src/mocks intercept /api/*
  • Production requires VITE_ENABLE_MSW=1 (no real backend)
  • No real database — in-memory mock DB in src/mocks/db.ts
  • Curated demo data — 13 regulations, 37 obligations, 15 CAPs
  • No AI backend — AI handlers return scripted mock responses
  • No bank integration — isolation by design for the demo
  • RBAC enforced client-side only (demo users in demo-users.ts)

◑ Target — Production

  • App server with REST API layer (replace MSW handlers)
  • PostgreSQL primary store; Object Storage for evidence
  • Set VITE_API_URL to backend; remove MSW flag
  • pgvector for regulation embeddings (RAG)
  • Redis for cache / sessions / rate limits
  • LLM Gateway + RAG + agents — real model calls with prompt logging
  • ESB / Kafka integration with bank IT systems (next slide)
  • SSO/AD, server-side RBAC, audit trail, encryption at rest
Migration path: keep the SPA + service/hook/type layers untouched — they are API-shape-stable. Swap the MSW handler layer for a real app server behind the same /api/* contract. The AI service abstraction (src/services/ai_service.ts) already isolates model calls.
04 · Data tier

Data tier deep-dive

Four storage engines, each with a distinct role in the compliance data lifecycle.

PRIMARY

🗄 PostgreSQL

Schema domains: regulations & dependencies, obligations, CAP, NCC, assignments, reports, users, org units (HO departments + branches), activity, audit logs.

Effective-status logic lives here: obligation status derived from linked CAPs (all Closed → completed).

BLOB

📎 Object Storage

S3 / MinIO for document ingestion (regulation PDFs), and per-entity evidence uploads.

Used by CAP FileUploadComponent and NCC investigation evidence (nccId-scoped).

SEMANTIC

🧬 Vector DB

pgvector (or managed Pinecone) storing regulation/article embeddings.

Serves RAG retrieval — semantic search across the regulation library for impact analysis & copilot grounding.

CACHE

⚡ Redis

Query cache (dashboard aggregations, report calendars), session store, rate-limit buckets for LLM gateway.

EWS trending computation cached here to keep the exec dashboard sub-second.

Data lineage: Master Table (org units) → NCC module → EWS report. NCC data depends on master table for ownerUnitId; EWS depends on NCC data for trending analysis. Regulations feed obligations → assignments → CAPs → NCCs.
05 · AI platform

AI platform deep-dive

Augmentation, not autonomy. Every AI output is advisory and gated by human approval.

RAG FLOW

🔁 Retrieval-Augmented Generation

Regulation PDF → OCR → parsing → chunking → embedding → Vector DB → RAG retrieval → LLM + compliance agents → rule evaluation → report / recommendation → human approval → banking systems.

ENDPOINTS

🧭 LLM Gateway

Prompt management, model routing, prompt logging, cost & rate controls.

🤖 Agent Orchestrator

Multi-agent workflows: fetch regulation → assess impact → draft CAP → suggest risk score.

📐 Rule + Impact Engine

Regulatory change analysis, policy mapping, impact % per business unit.

🛡 Explainability

Citations, confidence scores, ranked reasons — the AIExplanation component pattern.

Guardrails: model governance, prompt logging, human-in-the-loop review, feedback learning. No autonomous actions — AI suggests; approvers decide. Confidence indicators surface uncertainty to users.
06 · Integration

Bank IT interlinks

Where the compliance platform touches the bank's existing estate — and which way the data flows.

CORE

🏦 Core Banking / CIF

In: product & customer context for obligation scoping. Out: compliance flags back to customer/product records.

SIGNAL

🚨 AML Monitoring

In: transaction alerts & SAR data feed NCC creation. Out: closed NCC outcomes to AML case history.

CDD

🪪 KYC System

In: customer due-diligence status for AML obligation applicability. Enriches obligation owner assignment.

REMEDY

💸 LOS / Treasury

Out: CAP remediation status blocks loan origination / treasury limits when obligations are overdue.

RISK

📊 Risk Systems

Out: compliance risk scores & EWS signal feed credit / market / operational risk engines.

ANALYTICS

📈 DWH / Data Lake

Out: full compliance dataset for enterprise analytics & regulatory reporting (MDM-aligned).

DOCS

📑 ECM

Bi-di: evidence & policy documents sync with Enterprise Content Management for single source of truth.

PROCESS

⚙️ BPM

Out: CAP & assignment workflows surface as tasks in the bank's BPM; status synced back.

REGULATOR

🏛 SBV / NHCV

Out: generated regulatory reports & submissions to the State Bank of Vietnam portal.

Integration backbone: API Gateway + ESB + Kafka MQ carry all interlinks. Async events (alerts, status changes) over Kafka; synchronous lookups (CIF, KYC) over ESB/REST. IAM (SSO/AD) and audit logging span every touchpoint.
07 · Cross-cutting & closing

Security, observability & next steps

🔐 Auth & RBAC

SSO via Active Directory. Four roles (admin, executive, owner, approver) with permission matrix — currently client-side, target server-enforced.

📜 Audit & lineage

Append-only audit logs, full timeline per entity, data lineage tracking, prompt logging for every AI call.

🛡 Encryption

TLS in transit, AES-256 at rest, secrets manager, API security & model governance.

📡 Observability

Monitoring & alerting, Vercel Speed Insights (Core Web Vitals), backup & disaster recovery.

Build sequence

1

App server + PostgreSQL

Implement REST API behind the existing /api/* contract; migrate MSW handler logic into real services. Keep SPA & hooks untouched.

2

AI platform + RAG

Wire LLM gateway, embed regulation library into pgvector, replace scripted AI handlers with real model calls + prompt logging.

3

Bank ESB integration

Connect CIF/KYC/AML/Core Banking via ESB + Kafka; surface CAP/NCC outcomes back to bank systems; regulator report submission.
